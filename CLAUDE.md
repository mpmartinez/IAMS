# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

AssetDesk is a .NET 10 solution combining IT asset management (QR code scanning, assignments,
warranty tracking, offline mobile support) with a service desk (tickets, comments, attachments)
across multiple tenants. It consists of three projects:

- **AssetDesk.Api** - ASP.NET Core Web API on PostgreSQL (Npgsql)
- **AssetDesk.Web** - Blazor WebAssembly PWA frontend
- **AssetDesk.Shared** - Shared DTOs between API and Web

## Build Commands

```bash
# Build entire solution
dotnet build

# Run API (https://localhost:5021)
cd src/AssetDesk.Api && dotnet run

# Run Web (https://localhost:5022)
cd src/AssetDesk.Web && dotnet run

# Rebuild the stylesheet (scans .razor -> regenerates wwwroot/css/app.css)
npm --prefix src/AssetDesk.Web run build:css
# Or keep it watching while doing UI work
npm --prefix src/AssetDesk.Web run watch:css
```

Both projects need to run simultaneously for full functionality.

**Tailwind CSS:** the source is `src/AssetDesk.Web/Styles/app.css`, the config is
`tailwind.config.js`, and `wwwroot/css/app.css` is a committed, precompiled artifact.
`dotnet build`/`dotnet run` do **not** regenerate it - Tailwind used to run in the browser via
the Play CDN, and it does not any more. A *new* utility class, especially an arbitrary value
like `w-[130px]`, is simply missing at runtime (the element renders unstyled) until
`build:css` runs. Keep `watch:css` running while doing UI work, and bump the `?v=` on the
stylesheet link in `wwwroot/index.html` plus `cacheName` in `service-worker.published.js`
whenever the compiled sheet changes - it is served unhashed and the service worker precaches
it by exact URL.

Stop a running server before `dotnet build` - it holds a lock on the output DLLs and the build
fails with MSB3027 "file is locked by AssetDesk.Api", which reads like a code error but is not.

## Database

PostgreSQL via Npgsql. The connection string is supplied at runtime through
`ConnectionStrings__DefaultConnection` (user-secrets in development) and is never committed.
Migrations auto-apply on startup.

Tests run on in-memory SQLite (`TestDb.Create`), so a green suite does not prove a migration
applies on PostgreSQL - check generated SQL types when a migration matters.

```bash
# Create new migration
cd src/AssetDesk.Api
dotnet ef migrations add MigrationName

# Apply migrations manually (usually not needed)
dotnet ef database update
```

## Architecture

### Authentication Flow
1. API uses ASP.NET Core Identity with JWT tokens
2. Web stores JWT in localStorage via `AuthService`
3. `AuthStateProvider` manages authentication state
4. `ApiClient` attaches Bearer token to all authenticated requests

### Authorization is permission-based, not role-based
Policies in `Program.cs` map a name to a permission key, e.g.
`.RequirePermission("CanManageUsers", Permissions.UsersManage)`. Roles are just bundles of keys,
tunable per tenant at `/admin/roles`. Only `SuperAdmin` and `CanManageTenants` check a role
directly. Gate new endpoints on an existing key before inventing one - see the warning below.

The catalog is code-owned in `Authorization/Permissions.cs`; the database owns only the grants.

### API Response Pattern
All API endpoints return `ApiResponse<T>` wrapper:
```csharp
public record ApiResponse<T>(bool Success, T? Data, string? Message);
public record PagedResponse<T>(List<T> Items, int TotalCount, int Page, int PageSize);
```

### Offline Support (Web)
- `OfflineStorageService` - IndexedDB wrapper via JS interop
- `NetworkStatusService` - Online/offline detection
- `SyncService` - Queues actions offline, syncs when online
- JavaScript module at `wwwroot/js/offline-storage.js`

### QR Code Scanning
- `QrCodeService` (API) - Generates QR codes with asset URLs
- `wwwroot/js/qrScanner.js` - Html5Qrcode library wrapper
- `Scan.razor` - Scanner UI with offline fallback

## Key Entities

- **Asset** - Core entity with AssetTag (unique), DeviceType, Status, warranty info
- **AssetAssignment** - Tracks assignment history (who, when, return status)
- **WarrantyAlert** - Generated by `WarrantyCheckService` background job
- **ApplicationUser** - IdentityUser plus FullName, Department, TenantId, IsActive,
  IsSuperAdmin, MustChangePassword

## Naming (renamed from IAMS)

The app was renamed IAMS -> AssetDesk. Namespaces, projects, and UI branding all say AssetDesk.
Three things deliberately still say `iams` or `IAMS` - do NOT "finish" the rename without the
matching migration and deploy:

- **Permission keys** (`iams:assets:view`, etc.) are persisted in `RolePermissions`. Renaming the
  prefix without a data migration strips every role of every permission.
- **`Jwt:Issuer` / `Jwt:Audience`** are validated on every request. Changing them invalidates
  every token already issued.
- **Infrastructure** - the `iams.m2netsolutions.com` domain, `ghcr.io/*/iams-{api,web}` images,
  and the `iams-uploads` / `iams-data` volumes. Renaming a volume does not move its contents;
  attachment files live in `iams-uploads`.

## Passwords

An administrator never sets or learns another user's password. Both paths email a link to
`/reset-password` and let the user choose it themselves:

- **Creating a user** - `CreateUserDto` has no password field. The account is created with a
  random one (`PasswordGenerator`) and invited by email.
- **Resetting a user** - `POST /api/users/{id}/send-password-reset`, gated on
  `iams:users:manage`. Mails the link, then revokes refresh tokens.

`ApplicationUser.MustChangePassword` is what enforces it: while set, `Login` refuses even a
correct password. `ResetPassword` clears it. Send the mail *before* setting it - locking an
account whose invite failed to send strands the user with no way in.

`/api/auth/login`, `/forgot-password` and `/reset-password` are rate-limited; see
`RateLimitPolicies`.

## Gotchas

- **Adding a permission key needs a data migration.** `SeedData.EnsureRolePermissionsAsync` is
  gated on `Tenant.RolePermissionsSeededAt` and never re-runs, so a new key in `Permissions.All`
  reaches no existing tenant. Every current Admin would silently lack it.
- **`AuthorizeRouteView` renders its `Authorizing` and `NotAuthorized` fragments inside
  `DefaultLayout`.** `MainLayout` therefore mounts on anonymous pages like `/login` while auth
  resolves, and its `OnInitializedAsync` runs. Gate any API call there on an authenticated
  principal - an unauthenticated 401 that redirects with `forceLoad` becomes an infinite reload.
- **`ApplicationUser` is deliberately absent from `AuditSaveChangesInterceptor.AuditedTypes`.**
  Auditing it would serialise `PasswordHash` and `SecurityStamp` into every row. Admin actions on
  users write their own `AuditLog` entry instead.

## Testing

`dotnet test` - one project, `tests/AssetDesk.Api.Tests`.

Controllers are tested directly with real Identity stores over the test `AppDbContext`, not mocks:
`TestDb.Create`, `FakeTenantProvider`, `FakeEmailService`, `StubSubscriptionService`. A hand-built
`UserManager` has no token provider, so any path minting a password token needs
`RegisterTokenProvider(TokenOptions.DefaultProvider, new StubTokenProvider())`.

## Conventions

### Asset Status Values
`Available`, `InUse`, `Maintenance`, `Retired`, `Lost` (see `AssetStatus` class)

### Device Types
`Laptop`, `Desktop`, `Monitor`, `Phone`, `Tablet`, `Printer`, `Network`, `Server`, `Peripheral`, `Software`, `Other` (see `DeviceTypes` class)

### Frontend Styling
Tailwind CSS with custom theme. Dark mode supported via `dark:` prefix classes.

### API Endpoints Pattern
- `/api/assets` - CRUD for assets
- `/api/assignments` - Asset assignment/return operations
- `/api/reports` - Reporting endpoints (inventory, warranty, value)
- `/api/warrantyalerts` - Warranty alert management
- `/api/dashboard` - Dashboard statistics
